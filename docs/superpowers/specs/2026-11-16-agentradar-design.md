# AgentRadar 设计说明

日期：2026-11-16。状态：用户已确认总体方案；此文为设计基线。2026-11-17 已实现命令行研究 Agent、每日采集与可选网页，实际状态和未完成边界见 README.md 与 docs/IMPLEMENTATION.md。

## 1. 用户目标与范围

面向个人的 AI 前沿信息与实践助手。科研和工程都关注，以工程应用为主；每天阅读约 10～15 分钟，每周选一个可完成的实践任务。Windows 本地运行，生成可浏览中文日报。所有数量、时间、评分权重均是可调整的初始配置，不是已经测得的效果。

成功不是收集最多信息，而是输出有来源、少重复、可解释且能转化为行动的内容。第一版不自动安装、执行或修改外部项目，不建设多用户平台，不引入多智能体。

## 2. 架构与职责

固定流水线负责采集、规范化、持久化、去重、预算、报告和调度。单个研究 Agent 负责补充资料、比较变化和提出实践建议；它不能绕过工具权限及调用预算。

流程：采集 → 规范化并保存 → 初筛 → 结构化分析 → 有限补查 → 验证引用 → 编排日报 → 本地浏览和反馈。

各模块通过数据对象交互，不直接修改其他模块的内部状态。报告可以从已保存资料重新生成，无须再次采集。

| 模块 | 输入 | 输出与责任 |
|---|---|---|
| collectors | 来源配置、该来源检查点 | 原始条目、来源状态、候选检查点 |
| storage | 条目和运行结果 | 原子保存、历史查询、唯一性约束 |
| selection | 条目、历史、偏好 | 有上限的候选集合和过滤理由 |
| analysis | 候选及证据 | 结构化摘要、评分、引用、限制 |
| research | 待验证问题、只读工具、预算 | 补充证据或明确的信息缺口 |
| reports | 已验证分析、来源状态 | HTML、Markdown、日报记录 |
| web | 报告和反馈请求 | 仅本机可访问的页面、反馈持久化 |
| scheduler | 本地时间配置 | 单实例任务、日志与退出状态 |

## 3. 信息源与发现机制

完整第一版必须同时具备已知项目追踪和陌生项目发现。

- 已知项目：GitHub Releases。初始观察候选为 openai/openai-agents-python、langchain-ai/langgraph、modelcontextprotocol/python-sdk；列入观察不代表用户已学习这些框架。
- 陌生项目：GitHub Search。分别检索近期创建和近期更新的项目；主题包括工具调用、记忆、RAG、评测、编程工具、安全。保留少量宽主题候选，避免关键词把探索范围锁死。
- 研究：arXiv cs.AI、cs.CL、cs.LG RSS。论文关联仓库必须来自可追溯的资料，不由模型凭名称猜测。
- 后续扩展：厂商官方更新、Hugging Face 论文发现页。每个新增连接器先核验接口、访问限制和失败行为。

不把 GitHub 搜索结果称为 Trending 榜单。Star 是关注度信号；增长速度仅在已有连续快照时计算。首次启动不能声称已知增长趋势。

已核验的入口文档：
- https://docs.github.com/en/rest/releases/releases
- https://docs.github.com/en/rest/search/search
- https://info.arxiv.org/help/rss.html

## 4. 数据契约与存储

SQLite 保存以下实体；内部时间使用 UTC，报告按 Asia/Shanghai 展示。

| 实体 | 必要字段与约束 |
|---|---|
| item | source、external_id、version_key、title、url、published_at、first_seen_at、fetched_at、raw_text、content_hash；source + external_id + version_key 唯一 |
| event | event_id、关联 item ID；来源明确互相引用时优先合并，相似标题只产生候选关联 |
| analysis | item/event ID、evidence IDs、中文摘要、分项评分和理由、限制、模型标识、提示词版本、输入哈希 |
| run/source_run | 开始结束时间、来源状态、错误类型、请求和模型用量、检查点、采集缺口 |
| report/report_item | 报告日期、修订号、状态、选中事件及排序；修订同一日报不制造新的推荐记录 |
| feedback | 用户动作、条目 ID、时间；有用、暂时太难、不感兴趣、已完成实践 |
| practice | 目标、资料 ID、前置知识、预计时间、交付物、验收方式、用户确认的完成状态 |

缺失发布时间保持空值，不能用抓取时间冒充发布时间。分别保存发布时间和首次发现时间：旧项目首次发现进入“新发现”，不称为“今日发布”。

内容更新保留版本或历史分析。相同事件不反复推荐；有实质性新变化时允许再次推荐，并解释变化。用户收藏不等于掌握。

## 5. 筛选、研究与证据

建议初始分数为 0～5 分，加权排序：工程价值 30%、个人相关性 25%、证据质量 20%、新颖性 15%、实践可行性 10%。模型必须解释各项分数，未知信息不能按已知事实评分。

先移除精确重复和明确无关条目；关键词过滤只用于排序与削减候选，不作为唯一入口。完整第一版每天最多分析 30 条候选、深入研究 5 条，每条补充工具调用最多 3 次。候选量过大时按来源、主题和新颖性分层抽样；记录被预算跳过的数量。

工具范围：搜索公开仓库、读取发布说明和文档、读取论文摘要、查询本地历史和偏好。只允许 HTTPS 公共地址；解析和重定向后均拒绝本机、私网及其他非公网目标。工具结果是资料，不是系统指令。

停止条件：关键问题已得到证据支持、工具次数耗尽或总预算耗尽。模型输出证据 ID；程序从证据表解析链接，拒绝不存在的 ID。

事实、作者主张、模型建议分别标识。仅读到摘要必须标注；链接存在不代表结论可靠，仍须进行人工抽样评测。不得自动运行 README 命令或安装项目。

模型供应商通过适配层替换。未配置密钥时可运行基础日报；完整智能日报需要用户选定的模型服务。云端 API 会接收候选公开资料和必要偏好，即使其他组件运行在本地。密钥不入库、不进入报告或版本控制。

## 6. 日报和反馈体验

完整日报以中文输出，最多 3 条重点、2 条补充、1 条意外发现；没有合格内容可以留空。工程与研究约 70:30 是长期倾向，不按天强行配额。

每条包括：发生了什么、为什么相关、证据和限制、原始链接、发布和采集时间、阅读建议、可选行动。基础概念可进入“补基础”栏目，但不能冒充新进展。

首页显示报告生成时间、是否降级、各来源成功/失败/部分完成，以及最后成功采集时间。原始标题和外部文本必须 HTML 转义，链接限定 http/https；不渲染外部脚本。

四个入口：今日日报、历史记录、收藏与反馈、本周实践。收藏与反馈阶段加入本地 Web 服务，仅绑定 127.0.0.1，并检查写请求来源、防止跨站提交。更早阶段直接打开静态 HTML。

每周实践从用户标记有用的内容中选一个，明确目标、前置知识、预计投入、交付物、验收方式。完成状态由用户确认；估计时间与实际耗时分开记录。

## 7. 调度与可靠性

默认北京时间 08:30，使用 Windows 任务计划程序，配置错过触发后补跑；另提供手动运行入口。任务互斥，使用明确工作目录和虚拟环境 Python 绝对路径。

各来源独立运行、独立记录检查点。只有相应分页结果完成持久化后才推进检查点。保留重叠采集窗口并通过唯一键去重；首次启动和长时间断线要限制回补量并显示缺口。

RSS 不是无限历史档案。缺失历史只有在加入支持回补的接口后才能补齐，未补齐必须明示。一个来源失败不影响其他来源。所有来源失败时显示失败报告，不保留会误导为最新结果的旧页面。

HTTP 设置超时、大小上限和有限重试，尊重限流及 Retry-After。模型结构化输出失败允许一次有预算约束的修复，再失败降级为标题、日期、链接列表。报告写入临时文件后原子替换，避免半成品覆盖可读报告。

模型预算配置包含输入/输出 Token、调用数和运行耗时上限，所有重试和研究步骤均计入。模型定价由实际供应商确定，未知价格时只报告用量，不虚构费用。

## 8. 分阶段交付与验收

| 阶段 | 交付 | 验收 |
|---|---|---|
| M1 基础闭环 | GitHub Releases、arXiv、SQLite、静态 HTML、手动运行 | 两类来源可保存；重复运行不重复入库；来源失败可见；离线样本可生成页面 |
| M2 可用日报 | 陌生项目搜索、版本化存储、中文分析与引用、Markdown、限流回补、预算和 Windows 定时 | 未配置模型仍可降级；每日运行稳定；新发现与新发布区分；运行和报告可追溯 |
| M3 研究 Agent | 有限工具调用、证据补查、历史比较、安全边界 | 能对不同证据缺口选择工具；预算和停止条件有效；不执行外部指令 |
| M4 学习闭环 | 本地网页反馈、周实践、质量评测 | 反馈持久化；收藏不推断掌握；任务有验收和人工完成确认 |

M1 是基础里程碑，不单独宣称为完整智能体。完整第一版完成 M1～M4。初期静态报告保留外文原始标题，并明确尚无 AI 中文分析。

质量评测使用约 40 条人工检查样本，覆盖重复消息、旧项目、新发布、只有摘要的论文、无证据宣传和不可信指令。统计摘要支持率、重复推荐率、用户相关性、来源采集成功率、耗时与模型用量。连续运行一周后的结果才可作为项目成果。
